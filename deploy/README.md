# Развёртывание Aurum Site

Сайт живёт отдельно от Aurum Panel: `/opt/aurum-site`, системный пользователь `aurumsite`, своя PostgreSQL `aurum_site`, API на локальном `127.0.0.1:3007`. Nginx отдаёт React и проксирует `/api/`; административная панель и её БД не меняются.

Состояние на 26.09.2026: сайт доступен по HTTPS на `aurumgg.ovh` (www перенаправляет на основной домен). Сертификат и пробное продление проверены; hook `certbot-reload-nginx.sh` применяет обновлённый сертификат. Аккаунт `BogOtec` создан с подтверждённой почтой; временный пароль не хранится в репозитории. SMTP ещё не подключён, поэтому регистрация и письма отключены. Привязка Minecraft и каталог гильдий пока не подключены к игровым данным.

1. Создать пользователя и пустую PostgreSQL с правом только на свою БД. Локальное подключение через Unix socket и peer-аутентификацию не требует пароля БД в конфиге.
2. Клонировать репозиторий, выполнить `corepack pnpm install --frozen-lockfile`, затем `corepack pnpm --filter @aurum-site/web build` и `corepack pnpm --filter @aurum-site/api test` под `aurumsite`.
3. Создать `/etc/aurum-site` (root:aurumsite, `0750`) и однократно запустить `node deploy/init-env.js` от root. Скрипт создаёт `api.env` только если файла ещё нет; секрет генерируется локально и не выводится. Дать файлу владельца root:aurumsite и создать симлинк `apps/api/.env` на него.
4. Запустить миграцию `corepack pnpm --filter @aurum-site/api db:migrate` под `aurumsite`, затем однократно `BOOTSTRAP_EMAIL=... BOOTSTRAP_NICKNAME=... corepack pnpm --filter @aurum-site/api bootstrap:owner`. Она работает только на пустой БД при закрытой регистрации и отключённой почте, создаёт подтверждённый аккаунт и печатает временный пароль один раз. Сменить его после первого входа в настройках.
5. Установить `deploy/aurum-site-api.service`; API слушает только loopback. Установить `deploy/nginx-staging.conf` до DNS/сертификата, затем получить Let's Encrypt для `aurumgg.ovh` и `www.aurumgg.ovh` и заменить конфиг на `deploy/nginx-production.conf`. Установить `deploy/certbot-reload-nginx.sh` в `/etc/letsencrypt/renewal-hooks/deploy/` с правами `0755`.
6. До SMTP `EMAIL_ENABLED=false`, `REGISTRATION_ENABLED=false`. При первом старте API создаёт таблицы настроек сайта, администраторов, профилей, аватаров и обложек; эти флаги становятся начальными значениями в БД. Если администратор был создан до появления этих таблиц, однократно выполнить `SITE_ADMIN_EMAIL=адрес corepack pnpm --filter @aurum-site/api admin:grant` после проверки подтверждённой почты. Новый `bootstrap:owner` делает это сам. Режим обновления по умолчанию выключен.
7. После входа администратором заполнить SMTP в блоке «Настройки сайта», сохранить параметры и отправить тестовое письмо. Проверить доставку, затем включить «Письма» и «Регистрация». При изменении SMTP они снова отключаются до нового теста. Пароль SMTP зашифрован ключом, производным от `BETTER_AUTH_SECRET`; при ротации секрета нужно сначала перенастроить SMTP. Проверить регистрацию, подтверждение, сброс пароля и SPF/DKIM/DMARC.

Ник сайта: 3–20 латинских букв, цифр или `_`; уникальность проверяется без учёта регистра. Minecraft-ник появляется в игровом профиле отдельно после привязки.

Для обновления выполнить `git pull --ff-only`, `corepack pnpm install --frozen-lockfile` и сборку веб-приложения из шага 2. Если изменился API, после тестов перезапустить `aurum-site-api.service`; перед заменой конфигурации Nginx выполнить `nginx -t`. Для обложек в Nginx требуется `client_max_body_size 5m`. Не запускать повторно `bootstrap:owner` и не перезаписывать `/etc/aurum-site/api.env`.

На этой VDS сейчас нет автоматического бэкапа БД Aurum Site. Не путать его с `aurum-backup.timer`: тот архивирует только БД административной панели. До открытия публичной регистрации стоит отдельно решить схему резервного копирования сайта и восстановления.

## AurumLink

Нужен Companion 0.13.6+ и обновлённый API Aurum Panel. Нового публичного
порта не требуется: сайт обращается к панели приватно, панель — к уже
настроенному Companion. Staff-аккаунты, ключи Pterodactyl и базы игры сайту
не выдаются.

1. Сгенерировать отдельный секрет: `openssl rand -hex 32`. В `/etc/aurum-panel/api.env` указать `SITE_BRIDGE_TOKEN` и `SITE_BRIDGE_SERVERS` — UUID публикуемых Minecraft-серверов через запятую, не короткий Pterodactyl identifier.
2. В `/etc/aurum-site/api.env` указать `AURUM_PANEL_BRIDGE_URL=http://10.0.0.1:3001` и тот же секрет в `AURUM_PANEL_BRIDGE_TOKEN`. Сохранить права `0640`, не менять существующие секреты авторизации/SMTP. Обе пустые переменные отключают мост.
3. В `plugins/AurumCompanion/config.yml` поставить `site.enabled: true`, `site.base-url: "https://aurumgg.ovh"` и правильный `panel.server-id`. Приватный HTTP-порт и существующий токен Companion оставить прежними.
4. Перезапустить API панели и сайта. При старте сайт добавляет `site_minecraft_profile` и `site_link_attempt`; существующие пользователи, сессии, изображения и настройки не перезаписываются. Перезапуск Minecraft выполняется отдельно владельцем.

Мост имеет только `GET /api/internal/site/minecraft/servers` и
`POST /api/internal/site/minecraft/consume`: отдельный bearer-secret,
приватный IP и allowlist серверов. На сайте привязка требует действующей
подтверждённой сессии и правильного Origin; SQL-уникальность не позволяет
присвоить профиль второй учётной записи. Разрешены пять попыток за пять
минут на аккаунт. Код передаётся в JSON, в кликабельной ссылке находится
только в fragment и убирается после открытия формы. POST не повторяется
автоматически при сетевой ошибке: сначала читается сохранённая привязка.
