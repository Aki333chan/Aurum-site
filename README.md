# Aurum Site

Игровой сайт сообщества Aurum. Репозиторий отделён от административной Aurum Panel: игровые аккаунты, сессии и права не смешиваются с персоналом панели.

## Что готово

- Страницы входа, регистрации с обязательным уникальным ником, подтверждения email, восстановления и смены пароля. Светлая тема доступна ещё до входа и сохраняется в браузере.
- API авторизации на Node.js, отдельная PostgreSQL и настраиваемый из админского блока SMTP. Подтверждение email обязательно до первого входа; привязка Minecraft-профиля — отдельный последующий шаг.
- Отдельные настройки сайта для администратора: SMTP, регистрация, режим обновления (по умолчанию выключен), период смены изображений. Аватар и обложка загружаются вместе в редакторе профиля не чаще раза в 24 часа для каждого; прежнее изображение заменяется в единственной записи БД. Браузер обрезает и преобразует поддерживаемые им растровые изображения до 20 МБ в PNG, сервер хранит WebP; обложка приводится к 1600×400, аватар — к 256×256. SVG и форматы, которые браузер не откроет, отклоняются.
- Закрытый сессией интерфейс сайта. Общий профиль аккаунта работает на реальных данных: владелец редактирует короткую строку и описание, другой вошедший пользователь может открыть `/u/<ник>` и увидеть аватар и публичный текст без email. Привязка Minecraft через `/aurumlink` работает через отдельный защищённый мост; настоящий ник, сервер, UUID и дата привязки доступны владельцу. Посетители видят только игровой ник и сервер. Игровых балансов, статистики, настоящих гильдий, публикаций и 2FA пока нет.
- Форма не выдаёт локальную «фальшивую сессию»: без доступного API войти нельзя.
- Короткие условия использования (`/terms`) и политика приватности/GDPR/RODO (`/privacy`): полноэкранное окно, ссылки до входа и под выходом, обе темы. Ближайшие игровые и социальные функции предусмотрены условно. [Тексты, границы и обязанности при развитии](docs/legal.md); это рабочая редакция, не юридическая сертификация.

## Привязка Minecraft

Войти на игровой сервер, авторизоваться и написать `/aurumlink` или `/alink`.
Открыть ссылку из чата, войти на сайт и нажать «Привязать профиль». Можно также
ввести код вручную на `/minecraft/link`. Код действует пять минут, одноразовый;
повтор команды отменяет предыдущий код. Не передавать его другим людям.

На одном сервере можно привязать один игровой профиль к одному аккаунту сайта.
Уже привязанный профиль не переносится автоматически. Привязки хранятся в
PostgreSQL сайта и сохраняются при перезапуске игры; игровые пароли и финансы
не копируются. Техническая настройка — в [deploy/README.md](deploy/README.md).

## Локальный запуск

Нужны Node.js 22+, pnpm 11 и отдельная PostgreSQL. SMTP нужен для открытия публичной регистрации, но не для входа заранее подтверждённого аккаунта.

1. Выполнить `pnpm install` в корне репозитория.
2. Скопировать `apps/api/.env.example` в `apps/api/.env` и заполнить своими значениями. `BETTER_AUTH_URL` — точный публичный адрес сайта: локально `http://127.0.0.1:5173`, при публикации `https://aurumgg.ovh`. `BETTER_AUTH_SECRET` — случайный секрет длиной не менее 32 символов; не добавлять его и пароль SMTP в Git. До настройки почты оставить `EMAIL_ENABLED=false` и `REGISTRATION_ENABLED=false`.
3. Создать пустую базу для сайта и запустить `pnpm --filter @aurum-site/api db:migrate`.
4. В отдельных терминалах запустить `pnpm api:dev` и `pnpm dev`. Vite направляет `/api` на локальный API (`127.0.0.1:3007`).
5. После входа администратором заполнить SMTP в блоке «Настройки сайта», сохранить и отправить тестовое письмо. Убедиться, что оно пришло, затем включить «Письма» и «Регистрация». Затем проверить регистрацию → письмо → подтверждение → вход → выход → восстановление пароля. Изменение SMTP снова выключает письма и регистрацию до повторной проверки.

Проверки кода: `pnpm build`, `pnpm api:test`, `pnpm audit --prod`.

При публикации отдавать сайт и `/api` с **одного HTTPS-домена**; прокси должен перенаправлять `/api` в локальный API и перезаписывать `X-Real-IP` реальным адресом посетителя для ограничения запросов. Не открывать порт 3007 наружу, не публиковать dev-сервер Vite. До проверки писем, миграции, DNS почты и резервного копирования БД публичную регистрацию не включать. Подробности VDS — в [deploy/README.md](deploy/README.md).

## План границ системы

- `apps/web`: React/Vite, интерфейс игроков.
- `apps/api`: авторизация и будущие социальные данные в собственной PostgreSQL.
- Ник сайта выбирается при регистрации, хранится отдельно от игрового ника и уникален без учёта регистра. Email не является публичным именем.
- Minecraft/Paper: отдельный одноразовый код `/aurumlink` выдаётся авторизованному игровому игроку. Узкий приватный мост через Aurum Panel позволяет только получить список опубликованных серверов и обменять код на подтверждённый UUID/ник; сайт не получает административные права панели. Код не нужен для регистрации на сайте.
- AurumGuilds и AurumCore остаются источником истины для членства, рангов и балансов. Сайт хранит лишь собственные социальные данные и запрашивает ограниченные действия с проверкой прав на стороне игры.

## Следующие этапы

1. После запуска Minecraft проверить живую привязку через `/aurumlink`, просроченный/повторный код и сохранение связи после перезапуска. При выпуске 0.13.6 игровой сервер остаётся остановленным по просьбе владельца.
2. Подключить настоящие данные Minecraft: личную статистику, гильдию только внутри игрового профиля, каталог гильдий и новости. Демонстрационные значения заменить, а не смешивать с реальными.
3. Добавить приватность, заявки и управление гильдией, публикации в общей/игровой/гильдейской ленте, комментарии и модерацию с проверкой игровых прав на стороне сервера. Для публикаций заранее предусмотреть жалобы, лимиты частоты, безопасный рендеринг и постраничную загрузку.
4. Добавить необязательную 2FA для игроков и обязательную для персонала сайта; проверить нагрузку, безопасность и отдельно согласовать резервное копирование данных сайта.
