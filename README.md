# Aurum Site

Игровой сайт сообщества Aurum. Репозиторий отделён от административной Aurum Panel: игровые аккаунты, сессии и права не смешиваются с персоналом панели.

## Что готово

- Страницы входа, регистрации, подтверждения email, восстановления и смены пароля. Светлая тема доступна ещё до входа и сохраняется в браузере.
- API авторизации на Node.js, отдельная PostgreSQL и отправка писем через SMTP. Подтверждение email обязательно до первого входа; привязка Minecraft-профиля — отдельный последующий шаг.
- Закрытый сессией интерфейс сайта. Главная, Minecraft, гильдии и профиль внутри пока остаются **демонстрационными экранами**; игрового моста, настоящей статистики, публикаций и 2FA ещё нет.
- Форма не выдаёт локальную «фальшивую сессию»: без доступного API войти нельзя.

## Локальный запуск

Нужны Node.js 22+, pnpm 11, отдельная PostgreSQL и работающий SMTP-сервер.

1. Выполнить `pnpm install` в корне репозитория.
2. Скопировать `apps/api/.env.example` в `apps/api/.env` и заполнить своими значениями. `BETTER_AUTH_URL` — точный публичный адрес сайта: локально `http://127.0.0.1:5173`, при публикации `https://aurumgg.ovh`. `BETTER_AUTH_SECRET` — случайный секрет длиной не менее 32 символов; не добавлять его и пароль SMTP в Git.
3. Создать пустую базу для сайта и запустить `pnpm --filter @aurum-site/api db:migrate`.
4. В отдельных терминалах запустить `pnpm api:dev` и `pnpm dev`. Vite направляет `/api` на локальный API (`127.0.0.1:3007`).
5. Проверить полный сценарий: регистрация → письмо → подтверждение → вход → выход → восстановление пароля. Без реальных PostgreSQL и SMTP это пока не проверено сквозным тестом.

Проверки кода: `pnpm build`, `pnpm api:test`, `pnpm audit --prod`.

При публикации отдавать сайт и `/api` с **одного HTTPS-домена**; прокси должен перенаправлять `/api` в локальный API и перезаписывать `X-Real-IP` реальным адресом посетителя для ограничения запросов. Не открывать порт 3007 наружу, не публиковать dev-сервер Vite. До проверки писем, миграции, DNS почты и резервного копирования БД публичную регистрацию не включать. Сайт на VDS пока **не развёрнут**.

## План границ системы

- `apps/web`: React/Vite, интерфейс игроков.
- `apps/api`: авторизация и будущие социальные данные в собственной PostgreSQL.
- Minecraft/Paper: одноразовый код `/aurumlink` будет выдаваться уже авторизованному игровому игроку. Реализация моста ещё впереди; код не нужен для регистрации на сайте.
- AurumGuilds и AurumCore остаются источником истины для членства, рангов и балансов. Сайт хранит лишь собственные социальные данные и запрашивает ограниченные действия с проверкой прав на стороне игры.

## Следующие этапы

1. Подключить отдельную PostgreSQL и SMTP, применить миграцию и провести живой тест регистрации, писем и восстановления пароля; подготовить почтовые SPF/DKIM/DMARC.
2. Реализовать `/aurumlink` и одноразовую привязку Minecraft-профиля через узкий защищённый мост.
3. Подключить настоящие данные Minecraft: личный профиль, каталог гильдий и новости. Демонстрационные значения заменить, а не смешивать с реальными.
4. Добавить приватность, заявки и управление гильдией, ленты и модерацию с проверкой игровых прав на стороне сервера.
5. Добавить необязательную 2FA для игроков и обязательную для персонала сайта; после проверки нагрузки и безопасности развернуть сайт на `aurumgg.ovh` отдельно от панели администраторов.
